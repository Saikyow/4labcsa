# Соответствие DataPath реализации

Схема: [DataPath.svg](../img/DataPath.svg). Источники: [machine.py](../machine.py),
[isa.py](../isa.py), [cache.py](../cache.py). SVG — редактируемый векторный исходник;
для изменения подписей не нужно восстанавливать схему из PNG.

## Что уточнено

Старая схема в основном правильно показывала пути данных. Новая явно показывает
преобразование operand24, порядок входов АЛУ, флаги IE/INT и связь с CU.
Имена управления совпадают с полями `Signals`, а не с условными `latch_*`.
Если поле выбора равно `None`, соответствующий регистр сохраняет значение.
Одинаковые имена синих терминалов — одна сеть; это позволяет не проводить
длинные пересекающиеся линии через весь лист.

| Узел | Реализация и смысл |
|------|--------------------|
| MUX PC | `pc_mux()`: PC + 4, IR.operand, RS[RSP-1], 0x0004 |
| MUX AR | `apply()`: старый PC либо старый TOS |
| MUX TOS | `tos_mux()`: ALU, NOS, IMM, MDR как int32, токен порта 0 |
| DS и SP | `data_stack()`: сохранение старого TOS; NOS = DS[SP-1] |
| RS и RSP | `return_stack()`: сохранение старого PC; вершина RS[RSP-1] |
| ALU | `alu(IR.opcode, NOS, TOS)`; унарные операции используют только TOS |
| IR и расширение | `decode()`: opcode8 + operand24; знак учитывается только для push |
| Память | `memory_access()`: адрес AR, данные записи TOS; READ заполняет MDR |
| Ожидание | `tick()`: запрос запускается один раз, затем выдерживается Access.ticks |
| Прерывание | `next_phase()`: IE && IRQ после инструкции; отдельный такт входа |

Слова данных на схеме имеют ширину 32 бита, opcode — 8 бит, поле operand — 24 бита.
Адреса байтовые, доступ только к выровненным словам. В Python PC и AR — обычные
целые; проверка адреса выполняется при обращении к памяти. Схема не вводит
дополнительного усечения PC/AR до 32 бит.

## Почему запись в память идёт из TOS

Перед `store` адрес находится в TOS, значение — в NOS. Это соответствует
`CodeGen.store()`: сначала вычисляется значение, потом адрес.

| Шаг исполнения | Одновременные действия |
|----------------|------------------------|
| 1 | AR <- старый TOS; TOS <- старый NOS; SP-- |
| 2 | mem[AR] <- TOS через кеш; при промахе CU ждёт завершения |
| 3 | TOS <- текущий NOS; SP-- |

В шаге 2 в TOS уже находится значение. Соединять вход записи кеша напрямую
с NOS было бы неверно для существующей последовательности тактов.

## Выборка, вызов и возврат

Выборка начинается с `AR <- PC`. Следующий шаг читает память, декодирует MDR в IR
и увеличивает PC на 4. При промахе шаг чтения занимает несколько тактов;
IR и PC обновляются только после ожидания.

Поэтому `call` сохраняет текущий PC, уже указывающий на следующую инструкцию.
Дополнительный `+4` на входе RS дал бы неверный адрес возврата.
`ret` и `iret` читают RS[RSP-1] до уменьшения RSP.

## Ввод и прерывания

Устройство ввода хранит один токен и IRQ. Расписание обновляется каждый такт,
в том числе во время ожидания памяти. Новый токен может затереть непрочитанный.
`in 0` читает значение и сбрасывает IRQ; само принятие прерывания IRQ не снимает.
Номер порта задаёт IR.operand: он не является значением, которое кладётся в стек.

После завершения инструкции CU проверяет IE && IRQ. В отдельном такте входа
выполняются RS.push(PC), PC <- 0x0004, IE <- 0, INT <- 1. Стек данных не сохраняется
автоматически. `iret` восстанавливает PC, устанавливает IE и сбрасывает INT.
INT хранится для отображения состояния; в условии приёма IRQ участвуют IE и IRQ.

## Граница модели памяти

Кеш общий для инструкций и данных: 16 наборов, 2 пути, 4 слова в строке,
LRU, write-back, write-allocate. Заполнение и вытеснение передают строку целиком.
Попадание занимает 1 такт, промах 11, промах с грязным вытеснением 21;
прямой доступ без кеша — 10.

В `cache.py` операция и изменение кеша/RAM выполняются сразу при запросе и
возвращают `Access(value, ticks, event)`. CU моделирует задержку счётчиком;
аппаратного протокола req/ready и потактового контроллера заполнения здесь нет.
MDR также заполняется в начале чтения, но IR/TOS используют его только после
ожидания. Утверждение, что абсолютно все изменения модели происходят на одном
фронте, было бы неточным.
